# HD-1910 servo variant

The stock Microduck body on Feetech **HD-1910-C001** servos (same footprint as
the XL330, so a drop-in), trained with the velocity recipe. Branch `hd1910`.

- Tasks: `Mjlab-Velocity-Flat-MicroDuck-HD1910` and
  `Mjlab-Velocity-Flat-Backlash-MicroDuck-HD1910` (experiment name
  `velocity_hd1910`). Same 61-D obs / 14-target action contract as every other
  policy in the family.
- Built as an **overlay** on `make_microduck_velocity_env_cfg()` through
  `make_hd1910_variant` (`tasks/hd1910.py`). Keep HD-1910-specific changes in
  that overlay, the actuator subclasses and the HD-1910 robot files, not in the
  shared velocity cfg, so merges from `upstream/develop` stay cheap.

## Status (2026-10-16): simulation only

- The actuator model is **provisional**: datasheet kt and R, XL330 friction and
  rotor inertia, XL330 DR ranges (`actuator/params/hd1910_provisional_m6.json`).
  Nothing has run on a real HD-1910. Treat every sim result as a feasibility
  check until a `bam` fit on a real servo replaces that file.
- `hd1910_v1` (6000 iterations, stock HOME stand pose). Under harness v2
  (`runs/hd1910_v1_final_eval_h2.json`, training-like delay, 3 replicas): turns
  at full command (+1.02 / −1.07 rad/s), tracks 0.2 → 0.09 and 0.3 → 0.16 m/s,
  no falls on the schedules, one replica falls at the 0.4 m/s standing kick.
  **Dead zone below ~0.15 m/s**: 0.10 m/s forward, back and left all give
  0.00 m/s. Standing costs ~0.13 N·m RMS on a hip roll, up to a third of the
  continuous rating. The 250-iteration checkpoint still walked at 0.10; the
  standing curriculum (2 → 25 % of envs) absorbed the slow region.
- **Stand pose** (`robot/hd1910_pose.py`): knee −0.6, hip_pitch −0.7821,
  ankle +0.1821, hip roll 4.5°. On this body the "straight" leg is a 121°
  dogleg, so the stock pose carries a 0.055 N·m gravity lever on each knee;
  extending the knee and easing the roll cuts the legs' standing heat by 82 %
  (`scripts/stand_torque.py`, `runs/stand_torque_*.json`). HOME_FRAME is
  untouched for the XL330 tasks.
- **Recipe overlay** (`tasks/hd1910.py`): `track_linear_velocity_fine` (xy
  Gaussian, std 0.10, on a 0.5 s EMA, weight 2.0, next to the stock term), a
  slow-command bucket (15 % of envs creep at 0.05–0.15 m/s on one axis), and
  `stand_torque` (the legs' Σ τ² at zero command, weight −2.0: prices bracing).
  Base velocity recipe untouched.
- `hd1910_v2` = merged recipe + stand pose + overlay (fine weight 1.0), 6000
  iterations (`runs/hd1910_v2_*_eval.json`, 3 replicas): 0.20 / 0.30 m/s now
  track at 0.20 / 0.27 (v1 0.09 / 0.16), back 0.10 at −0.10, turning 1.0–1.2,
  no falls on the schedules. **Fails** the gate table on forward 0.10 (0.000;
  it walked at 0.074 at iteration 1000 and folded it back into standing by
  2000, when the standing share reached 25 % and the action-rate tax −1.0),
  left 0.10 (0.057) and standing torque (hip roll 0.095 N·m: the policy
  **braces**, commanding the hip rolls 0.22 rad inward and the knees 0.14 rad
  against the floor with the joints at default, which the pose reward cannot
  see). Falls at the 0.4 m/s kick while walking in all replicas (reported,
  not gated).
- `hd1910_v2b` = v2 + fine weight 2.0 + `stand_torque` (legs' Σ τ² at zero
  command, weight −2.0): training (`runs/hd1910_v2b.log`).
- A ten-servo head-on-hips model exists (`robot/microduck_hoh/`, 0.67 kg) but has
  no task and has never been trained. Parked.

`infer_policy.py` carries its own copy of the HD-1910 actuator constants; the
test file locks them to `microduck_hd1910_constants.py`. Change both or the
test fails. The stand pose is not copied: every consumer imports
`robot/hd1910_pose.py`, and `tests/test_joint_layout.py` locks the scene
keyframe to it.

## Commands

```bash
# smoke test first, always
uv run train Mjlab-Velocity-Flat-MicroDuck-HD1910 --env.scene.num-envs 64 --agent.max_iterations 5 --agent.logger tensorboard
# train
uv run train Mjlab-Velocity-Flat-MicroDuck-HD1910 --env.scene.num-envs 4096 --agent.logger tensorboard
# export (normalizer baked in; the only valid path to an ONNX)
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck-HD1910 --checkpoint-file logs/rsl_rl/velocity_hd1910/<run>/model_5999.pt --onnx-file runs/out.onnx
# evaluate (3 replicas, training-like delay), compare against the baseline, render, rehearse
uv run scripts/eval_walk.py --walking runs/out.onnx --hd1910 --replicas 3 --json runs/out_eval.json --trace runs/out_trace.npz
uv run scripts/eval_walk.py --compare runs/hd1910_v1_final_eval_h2.json runs/out_eval.json
MUJOCO_GL=egl uv run scripts/render_walk.py --walking runs/out.onnx --hd1910 --out runs/out.mp4
uv run scripts/infer_policy.py --walking runs/out.onnx --hd1910 --new-cmd-obs --joint-vel-lag 1
# stand-pose torque: one candidate (hip_pitch,knee[,roll_deg], left sign) or the sweep
uv run scripts/stand_torque.py --pose=-0.7821,-0.6,4.5
uv run scripts/stand_torque.py --sweep-roll --json runs/stand_torque.json
# tests
uv run --with pytest pytest tests/test_hd1910.py tests/test_joint_layout.py tests/test_pose_hold.py tests/test_eval_walk.py tests/test_determinism.py
```

`runs/` is ignored by git; keep exports, eval JSON and videos there. Tests that
need a policy use the newest `runs/hd1910_*.onnx` (or `MICRODUCK_TEST_ONNX`);
name throwaway exports otherwise.

## Servo in one paragraph

Stall 0.98–1.18 N·m and continuous 0.29 N·m at 6 V, 9.6 rad/s no-load, 1.6 A
stall, 21 g, 4.0–8.4 V. Feetech **HLS** protocol (not STS), 4096 counts/rev,
current in 6.5 mA units, factory position gains P 32 / D 40, firmware 3.46. The
"max torque" register (16, default 980 × 0.1 %) caps PWM duty, hence
`max_pwm = 0.98`; the protection current (reg 28) unloads the servo after the
over-current time (reg 38), it does not clamp, hence `max_current = None`.
This robot is thermally limited, not torque limited.
